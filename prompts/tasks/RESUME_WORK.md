# Recover and Continue Existing Work

Apply `context-recovery` before making changes.

Inspect repository instructions, git state, task cards, reports, decision logs, current implementation, tests, and recent verification evidence. Do not trust a statement that work is complete merely because it appears in a report or prior conversation.

Build a concise state ledger:

- Verified complete
- Implemented but unverified
- In progress
- Planned only
- Blocked by a material decision
- Stale or contradicted claims

Preserve uncommitted work. Continue from the smallest verified next step using one writer and the appropriate verification loop. Finish with a Decision Handoff that another person or session can trust.
