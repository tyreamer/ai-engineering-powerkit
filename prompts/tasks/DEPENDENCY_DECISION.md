# Evaluate a New Dependency or Vendor

Apply `dependency-due-diligence` and `change-impact-analysis`.

First inspect whether the current stack already provides the required capability. Verify current facts from primary sources when external information matters. Evaluate maintenance, adoption, security history, license, transitive dependencies, operational burden, portability, data handling, lock-in, cost, and exit path.

Compare build, reuse, and buy options against the actual requirement. Do not recommend adoption because a tool is popular or because it produces an impressive demo.
